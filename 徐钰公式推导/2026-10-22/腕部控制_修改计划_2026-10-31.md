## 0. 总原则与顺序

| 原则 | 理由 |
|---|---|
| **先修错，再加状态，最后补文章层** | 前两步不改闭环行为，可以单独验证、单独回滚；第三步才动控制结构 |
| **每步一个 commit，带测试或可观测证据** | 出问题能 `git revert` 单个提交，不用整轮回退 |
| **新状态先"只记录、不上控制"** | 先攒一段数据确认量级和符号，再决定增益，避免一上就振 |
| **不动 P4 的 PID 增益与 LUT** | 内环已实机整定过，本轮问题都在外环/接口层 |

依赖顺序：

```
阶段 0（修错） ──► 阶段 1（补状态，只观测） ──► 阶段 2（安全链用上新状态） ──► 阶段 3（文章层）
     0.5 天                 1–2 天                      1 天                      2–4 天
```

### 1.2 P0-2　软限位名存实亡

先给数（用文章六段常数手算，k 取草稿值 130380 counts/m）：

| 项 | 绳长变化 | 折算 counts |
|---|---|---|
| C1/pitch，0° → 25° | 24.65 mm | 3 214 |

**方案 A（推荐，真实限幅）**

```diff
-MOTOR_SOFT_LIMIT = 2000000  # counts 输出上界（≈int32 安全域，等效解除 ±5000；仅防溢出）
+# 闭环输出相对使能起点的最大偏移（counts）。这不是工程安全门限，是防前馈异常/
+# 防 int32 溢出的兜底；真正的行程保护是角度目标钳制 + P4 腱 LUT 裕量。
+# 依据（k≈130380 counts/m）：C1/pitch 在模型全包络（roll ±25°，pitch −24…45°）
+# 的绳长全跨度 65.40 mm ≈ 8528 counts，x1.2 余量 → 10234，取 11000。
+MOTOR_SOFT_LIMIT = 11000
```

再按实际 k 自动校正（防重新辨识后 k 变大）：

```python
def _soft_limit_counts(self) -> int:
    """按标定 k 与模型全跨度推导输出限幅；无标定时用常量。"""
    need = MOTOR_SOFT_LIMIT
    if self.wrist_calib is not None:
        k = max(abs(v) for v in self.wrist_calib.k_counts_per_m)
        need = max(need, int(math.ceil(1.2 * k * 0.0654)))   # 0.0654 m = 全跨度
    return min(need, 20000)                                   # 上限防标定异常
```

`_cl_tick` 里 `prm.soft_limit = self._soft_limit_counts()`；`_cl_tick_force` 的钳制同样用它。

**方案 B（保持现状，只正名）**

- 常量改名 `OUTPUT_GUARD_COUNTS`，注释写"PC 侧不设行程，依赖 P4 ±30719 与 LUT 裕量"；
- 删掉 `wrist_force_law.py:20`、`mmhand_scope.py:2742`、`wrist_control_law.py:14` 里"±5000"的过时说法；
- 启动时把生效值打进 `ctrl_log`，便于现场核对。

**取舍**：A 改行为（目标可能被钳），但换来一道兜底；B 不改行为，只消除文档/代码矛盾。**需要你选**（见 §7）。

**验收**：把 `wrist_calib.json` 的 k 临时 ×10，确认目标被钳在 `origin±11000` 而不是冲出去；恢复后正常。

## 2. 阶段 1：补齐状态量（不改控制行为，1–2 天）

### 2.1 关节角速度 ω（G1）

放 `_cl_tick` 取到 `roll/pitch` 之后，只记录、不上控制：

```python
def _update_omega(self, roll: float, pitch: float) -> None:
    """差分 + 30 ms 一阶低通。只用于观测/记录，暂不进控制律。"""
    now = time.perf_counter()
    if self._omega_t is not None:
        dt = now - self._omega_t
        if 1e-4 < dt < 0.1:
            wr = math.radians(self._angle_delta(roll, self._last_pose[0])) / dt
            wp = math.radians(self._angle_delta(pitch, self._last_pose[1])) / dt
            a = math.exp(-dt / 0.03)
            self._omega[0] = a * self._omega[0] + (1 - a) * wr
            self._omega[1] = a * self._omega[1] + (1 - a) * wp
    self._last_pose = (roll, pitch)
    self._omega_t = now
```

配套：
- 在 `__init__` 里初始化 `self._omega = [0.0, 0.0]`、`self._last_pose = None`、`self._omega_t = None`；
- 新通道 `wrist_wr`、`wrist_wp`（rad/s），进 `_build_channels`；
- 进 `registry`，参数监视窗口可选；
- 进 CSV 记录列。

**已知精度**：角度量化 0.022°、更新 100 Hz → 单拍速度量化约 2.2 °/s，低通后噪声约 5 °/s。够做趋势和判振，不够做 D 项。要更干净只能走 P4 速度上行（见 §7 决策 4）。

**验收**：手推 roll 约 30 °/s，看读数同号、量级对；静止时噪声 < 10 °/s。

## 4. 阶段 3：补文章层（2–4 天）

### 4.1 `wrist_alloc.py`：张力分配（G4）

### 4.2 力控入口升级（可选）

UI 增加"τ\*/t"输入 → 内部 `f* = allocate(...)` → 交给现有三路 PI。保留三路 f\* 直填作为调试模式。**不做这步也能先有力控**，只是目标要靠人试。

### 4.3 ∂R/∂q 与误差预算（G5）

按文章式 (30) 实现 `dr_dtheta(theta, axis, cable)`，与中心差分对拍（步长 0.2°，相对误差 < 1e-3）。再用式 (38) 在线算 |Δτ| 上界，做"力矩可信度"提示。

### 4.4 绝对绳长 / `wrist_home.json`（G3）

定义"模型零位 ↔ 电机 counts"的对应：存 `l_i^0 = c_i + s_ri(0) + s_pi(0)` 与三段电机零位 counts。之后 `l_i = l_i^0 + (counts_i − counts_i^0)/k_i`，文章 8 节的绳长→角度反解才能在实机跑。

### 4.5 重力前馈 g(q)（可选，G-动力学）

至少做 pitch 重力矩：`τ_g = m g l_c sin(θp)`，m、l_c 从 CAD 取。先离线拟合一个常系数，再上台架验证静态误差是否下降。这是位置环去掉稳态误差最省事的一步，比加积分更稳。
