# 积分钳制设计说明（供 review）· 2026-11-20

> 一句话：**积分必须有两道上限** —— ① 贡献上限（counts/拍）② 累积上限（N·s）。
> 只有①会出现"状态越攒越多、反向退不完"；只有②会让输出在误差很小时被顶满。
> 本文说明现在的实现、数值、接线、以及需要你拍板的地方。

---

## 1. 先明确输出语义：`step` 是**速率**，不是位置

三个力控模式的执行器是增量式的（`_apply_force_step`）：

```
本拍目标位置 = 基准 + step          step 单位 = counts/拍
```

所以 `step` 的物理身份是**速度**（100 Hz 下 1 counts/拍 = 100 counts/s）。
由此：

| 项 | 单位 | 物理身份 |
|---|---|---|
| `kp · e` | counts/拍 | 比例：误差越大爬越快 |
| `ki · ∫e` | counts/拍 | **积分：一个"速率偏置"**（不是位置偏置）|
| `max_step` | counts/拍 | 速度上限 |

**推论**：即使误差=0，只要 `∫e ≠ 0`，电机仍会以一个恒定速率爬行。
这就是"两道闸"的必要性 —— 你限制的不只是"它还能爬多快"，还有"它记住了多少历史账"。

## 2. 当前实现（`wrist_force_law._incr_step`，5 行核心）

```python
lim_state = (i_term_lim / ki) if ki > 0.0 else 0.0
if ki > 0.0:
    integ_i = max(-lim_state, min(lim_state, integ_i))      # ① 累积上限（每拍都夹）
i_term = max(-i_term_lim, min(i_term_lim, ki * integ_i))     # ② 贡献上限
raw = kp * e_i + i_term
du = max(-max_step, min(max_step, raw))                      # ③ 输出限幅
if ki > 0.0 and (abs(raw) < max_step or raw * e_i < 0.0):    # ④ 条件积分
    integ_i += e_i * dt
    integ_i = max(-lim_state, min(lim_state, integ_i))
```

**顺序为什么重要**：①②必须在③之前。若先算输出再夹状态，就出现"这一拍用超限状态算输出、
下一拍才夹"——那正是原来 `lim_state` 写在 `if` 里造成的问题。

### 2.1 这一轮改的两处

| 改动 | 原来 | 现在 | 为什么 |
|---|---|---|---|
| ① 的位置 | **只在"本拍要积分"时**才夹 | **每拍都夹** | 历史残留（如 250 N·s）能一直撑着贡献上限。你观察到的"C1 误差 0.02 N 却一直 +20 收绳"就是它 |
| ② 的数值 | `TENSION_I_TERM_LIM_ENABLED=False` → 退回 `max_trim`=**5000** | `True`、`COUNTS=**5**` | 5000 counts 等于"没有上限" |

## 3. 数值与单位（review 重点）

`TENSION_I_TERM_LIM_COUNTS = 5.0`，累积上限由它派生：`lim_state = 5 / ki`。

| `ki` | 累积上限 ∫e | 贡献上限 | 折合偏置张力 |
|---|---|---|---|
| 5 | 1.000 N·s | 5 c | 0.232 N |
| 10 | 0.500 N·s | 5 c | 0.232 N |
| **20（当前）** | **0.250 N·s** | **5 c** | **0.232 N** |
| 40 | 0.125 N·s | 5 c | 0.232 N |

（折合张力用 `S = 0.0464 N/count`）

**"0.25 N·s"的直觉**：误差 × 时间的累积量。

| 稳态误差 | 攒满要多久 |
|---|---|
| 0.5 N | 0.5 s |
| 0.1 N | 2.5 s |
| 0.02 N | 12.5 s |

**为什么是 5 而不是 40**（我一开始想用 40 = 2×max_step，算完发现不行）：

| `i_term_lim` | 历史 state=250 时第 1 拍 | 误差 0.02 N 时步长 | **零误差时步长** |
|---|---|---|---|
| 5000（旧） | 250.0 | **20（满）** | **20（满）** |
| 40 | 2.00 | **20（满）** | **20（满）** |
| 10 | 0.50 | 10 | 10 |
| **5（现在）** | 0.25 | **5** | **5** |
| 2 | 0.10 | 2 | 2 |

**40 顶不住**：`raw = 15×0.02 + 40 = 40.3 > max_step(20)` → 仍然满速。
只有把贡献上限压到 ≤ max_step 的 1/4，才能真正止住"误差小却满速"。

## 4. 三个模式的接线（**这里发现并修了一个不一致**）

| 模式 | 传进 `_incr_step` 的 `i_term_lim` | 修前 | 修后 |
|---|---|---|---|
| 张力 | `p.i_term_lim`（scope 传 `_tension_i_term_lim(mt)`）| 5 ✓ | 5 ✓ |
| 张紧 | `p.i_term_lim`（同上，经 `WristTensionParams`）| 5 ✓ | 5 ✓ |
| **力矩** | **`p.max_trim`（=5000）** | ❌ **等于没有钳制** | ✅ 5 |

**修法**（两处）：

```python
# wrist_force_law.py
class WristForceV2Params:
    __slots__ = (..., "i_term_lim")
    def __init__(..., i_term_lim=None):
        self.i_term_lim = (float(i_term_lim) if i_term_lim is not None
                           else (tension_i_term_lim_counts() or float(max_trim)))

    # wrist_force_v2_step
    ... _incr_step(..., p.kp_inner, p.ki_inner, dt, p.max_step, p.i_term_lim)

# mmhand_scope.py  _force_params_v2
    mt = self._cl_fval("max_trim", 3000.0, 1.0, 50000.0)
    ...
    i_term_lim=self._tension_i_term_lim(mt)
```

**注意**：如果**不显式传** `i_term_lim`，默认仍是 `tension_i_term_lim_counts() or max_trim`，
即"常量关掉时退回 max_trim"的旧行为 —— 这样旧测试/旧调用不会被突然改变。

## 5. 与其它参数的关系

### 5.1 死区（`deadband`）

张力律里：`if abs(e) <= deadband: e = 0.0`，但 `i_term` **仍然每拍给出 step**。

```
进死区 → e=0 → raw = 0 + 5 = 5 → step = 5 counts/拍（=500 c/s）
      → 张力很快又出死区 → 误差反向 → 积分回退
      → 在死区边界附近形成一个小极限环（幅度 ~deadband=0.05 N）
```

**这是增量式 + 积分 的固有形态**，不是 bug，但需要你知道：

| 现象 | 你可以选择 |
|---|---|
| 稳态在目标附近 ±0.05 N 内抖 | 接受（这就是死区的作用）|
| 觉得抖得比之前多 | 把 `COUNTS` 降到 1~2（蠕变更慢）|
| 想在死区内"泄放"积分 | 加 `if e==0: integ *= 0.98`（**我建议先不加**，会削弱摩擦补偿）|

### 5.2 `max_step`（20）

贡献上限 5 ≪ 20，所以正常情况积分永远不会把输出吃满；
只有在"误差持续几十秒"时才可能把积分攒到 5（这正是它该干的事）。

### 5.3 `max_trim`（5000，**这次没动**）

它是「相对进入点的累计行程」，与积分**无关**：
积分管"每拍走多少"，`max_trim` 管"总共最多走多远"。
它的问题（堵转保护弱）独立存在，建议测完积分再改。

### 5.4 状态何时清零

`_start_closed_loop` → `self._tension_state.reset()`（三个力控模式共用同一个 state 对象），
所以**每次启动闭环积分从 0 开始**，不会带着上一条绳的账。

## 7. 需要你拍板的 4 件事

| # | 问题 | 我的建议 |
|---|---|---|
| **1** | **贡献上限 5 counts（0.23 N）够不够压摩擦？** | 先用 5 测。若稳态总差 0.1~0.2 N 收不回来 → 抬到 **10**（0.46 N）；若收过头 → 降到 **2** |

| **3** | 死区内要不要"泄放"积分？ | **先不加**。会削弱摩擦补偿，等你实测稳态抖动再说 |
| **4** | `max_trim` 5000 → 2000 现在改吗？ | **等积分这项测完再改**，一次只动一个变量 |

## 8. 已知风险（诚实清单）

1. **死区极限环**：稳态会在 ±0.05 N（≈1 count）附近微振，幅度取决于 `COUNTS`。
2. **`ki` 变了，累积上限跟着变**（ki: 20→40 时 0.25→0.125 N·s）。这是"输出口径"的代价；
   若你希望累积上限固定，就要用第 7 节第 2 条的独立口径。
3. **没有台架验证**：上面全是数值实验 + 单测。真值要看明天那次 60 s 张紧跑出来的
   `trim` 斜率与 `τ` 抖动。
4. **力矩模式的钳制是今天才接上的**，之前它的积分一直是不限的 —— 如果你之前调过力矩模式的
   `ki`，那时的行为是在"无钳制"下观察到的，接上后可能有可见变化（更不容易过冲）。
