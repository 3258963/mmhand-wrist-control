## 1. 今天做完的事

### 1.1 控制环线程化（A 方案）✅

**问题**：`_cl_timer`（QTimer 10 ms）和主图/表格/曲线重绘**在同一个 GUI 线程**排队，
实测控制拍周期 **22~28 ms**（设计 10 ms）→ 只有 36~44 Hz。

**改法**：

| 文件 | 改动 |
|---|---|
| `mmhand_scope.py` | 新增 `_ClLoopThread(QThread)`：绝对时间表 + `time.sleep` 调度，抖 ~1 ms |
| | `_stop_closed_loop` 拆成「跨线程入口」+ `_stop_closed_loop_now`（GUI 线程执行） |
| | 新增 `_ui_call / _drain_ui_queue`：工作线程的 UI 写操作排队，GUI 每 20 ms 执行 |
| | `cl_status.setText(...)` → `_cl_status_set(...)`（7 处，自动排队） |
| | `_warn_batch_skip` 的 `_ctrl_status` 也改成投递 |

**实测（空载调度测试）**：

```
2 秒内跑了 200 拍 → 100.5 Hz
拍间隔：中位 10.02 ms  均值 10.00 ms  最大 10.58 ms
（原来 22~28 ms → 36~44 Hz）
```

**顺手修的速度语义**（`_apply_force_step`）：

```python
# 旧：out = 实测 + n   → 命令永远只领先实测 1 拍
# 新：基准 = 上一拍目标；若它落在实测后方（按 n 方向判）则退回实测
prev = self.targets.get(m)
ref = cur if prev is None else int(prev)
if (ref - cur) * n < 0:
    ref = cur
out = ref + n
```

让命令可以"领先"实测（伺服有跑道加速），但绝不落后（外力推走时立刻对齐）。

> ⚠ 注意：我**没能用数据证明这条一定必要**（仿真显示只领先 20 counts 也能跑到 1000 c/s）。
> 它属于"语义更正确、行为更接近直控"的改动，建议明天用台架复测确认。

### 1.2 张紧实测分析（三批诊断 CSV）

**新增工具**：`🔬 诊断 CSV` 按钮（20 Hz，14 列：位姿+三缆张力+τ+预紧+trim）
**新增分析器**：`tools/analyze_tight_diag.py`（τ 统计 / 能力对照 / 共模-差模分解 / 自动判 A-B-C）

**5 个文件的结论**：

| 预紧 | 下垂 pitch | 稳态 τ_roll | 稳态 τ_pitch | t_meas |
|---|---|---|---|---|
| 5 N | 0 → **19.55°** | +0.32 ± 3.72 mN·m | +1.64 ± 1.34 mN·m | 3.88~5.28 |
| 15 N | 0.18 → **16.90°** | +2.31 ± 14.49 mN·m | +0.36 ± 5.95 mN·m | 13.1~16.1 |

**三条硬结论**：

1. **τ 很小**（1~2 mN·m）→ 你担心的"耦合"不是 τ 误差，**是姿态漂移**
2. **预紧 5→15，下垂只少 2.6°** → "预紧不买刚度"被数据证实；但 τ 抖动涨 4 倍（基数变大）
3. **启动瞬间三缆是松的**（f = 0.07 / −1.91 / 0.00）→ 腕先自由下落 19°，之后才建张力

**绳长账**（解释 trim 为什么涨那么多）：

```
腕从 (0,0) 掉到 (4,19) → C1 需要放长 18.9 mm（≈ 2053 counts）
张力环实际收了 1213 counts → 净放 840 counts
⇒ C1 的"收绳"大部分在追腕的运动，不是在建张力
```

## 5. 问题清单（明天决定改不改）

> 每条给「方案 A / 方案 B」，标了**代价**和**我的建议**。

### P0-1 控制线程里仍在直接读 Qt 控件 ⚠

**现状**：`_cl_tick` 里有 8 处 `isChecked()`，`_read_cl_params()` 每 50 ms 读 13 个 `QLineEdit.text()`，
`_tension_guard` 读阈值框 —— 这些都发生在**工作线程**。Qt 规定控件只能在 GUI 线程访问。

**风险评估**：只读、无重绘，实践上很少崩；但**不是保证**，长期跑有隐患。

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | GUI 侧 50 ms 把「参数快照 + 轴使能 + 记录开关」打包成不变对象，工作线程只读快照 | ~50 行，控件读取全部消失 |
| B | 保持现状（读的是 bool/text 缓存，PySide6 实测可行） | 0 行，风险留给以后 |

---

### P0-2 启动瞬间松绳 → 腕先掉 17~19°

**现状**：张紧/张力启动时三缆可能接近 0 N，张力建立前腕自由下落。
**数据**：`f = 0.07 / −1.91 / 0.00` → 20 秒内 pitch 掉 19.5°。

| 方案 | 做法 | 效果 | 代价 |
|---|---|---|---|
| **A（推荐）** | 启动门禁加"预紧下限"：三缆实测都 ≥ 1 N 才允许切张紧；否则提示"先一键紧绳" | 一次性消除 19° 下落 | ~20 行 |
| B | 张紧启动首段限速（前 2 秒 max_step 减半） | 减轻下落冲击 | ~10 行，治标 |
| C | A1 重力前馈（起环锁 `τ_g0`） | 根治"不带载"问题 | 半天 |

### P0-3 积分饱和（`i_term_lim = max_trim = 5000`）

**现状**：`TENSION_I_TERM_LIM_ENABLED=False` → 退回 `max_trim`，等于**不限**。
**数据**：C1 的积分贡献涨到 ~288 counts，误差只剩 0.02 N 时仍**每拍 +20 满载收绳**。

| 方案 | 做法 | 效果 |
|---|---|---|
| **A（推荐）** | `TENSION_I_TERM_LIM_COUNTS = 40`（= 2×max_step），保持 ENABLED=True | 积分最多把 P 放大 2 倍，不会永久饱和 |
| B | 条件积分 + 反算（back-calculation）：饱和时把积分往回扣 | 更快退出饱和，但实现复杂 |
