# 力封闭可行域钳制（2026-11-20）

> **一句话**：力控/张紧**内部算模型用的角度**每帧先钳进力封闭可行域
> `roll ∈ [−15°, +10°]`、`pitch ∈ [−25°, +30°]`，再用钳后的角度求 `R`、`n̂`。
> 真实位姿（显示 / CSV 位姿列 / 位置环）**不受影响**。
>
> 解决的问题：位姿越界时 `positive_null_direction` 返回 `None` → 三个力控模式**直接拒启**，
> 且只报"无可行预紧区间"，看不出根因。现在改为**软降级 + 明确告警**。

---

## 1. 为什么需要

`positive_null_direction` 只在 **n̂ 全正**（力封闭成立）的姿态返回方向：

| 位姿 | n̂ | 后果 |
|---|---|---|
| roll −15…+10°，pitch −25…+30° | ✅ 存在 | 三缆力控正常 |
| roll ≤ −20° 或 ≥ +15° | ❌ 不存在 | 模式拒启 |
| pitch ≥ +35° | ❌ 不存在 | 模式拒启 |

在 `RANGE_DEG`（roll ±25°, pitch −25…+45°）里，只有 **45%** 的区域可用
（5° 网格扫描：74/165 点）。

---

## 2. 钳制链（代码）

```python
# mmhand_scope._force_geo
rm = MODEL_AXIS_SIGN[0] * roll                      # UI 角 → 模型角（roll 翻号）
rr_raw = radians(rm + zero_offset_roll)             # 加零位补偿
pr_raw = radians(pitch_model_deg(pitch) + zero_offset_pitch)
rr, pr, clamped = clamp_force_closure(rr_raw, pr_raw)   # ← 钳的是**角度**
if clamped:
    self._warn_pose_clamped(...)                    # 1 s 节流提示 + 安全事件
out = wrist_eval(rr, pr)                            # ← R/s 由钳后角算出
nd  = positive_null_direction(rr, pr, out_model=out)    # ← n̂ 同理
```

**逐位验证**（UI roll=+20°）：

```
+20° → 翻号 −20° → 钳到 −15° → wrist_eval(−15°, 0)
_force_geo 返回 R 第一行 = [+0.001482, −0.005820, +0.025040]
wrist_eval(−15°,0)  R 第一行 = [+0.001482, −0.005820, +0.025040]   ← 差 < 1e-12
```

---

## 3. 两个"角度副本"（容易误解的点）

| 副本 | 是否钳 | 用途 |
|---|---|---|
| **原始位姿**（编码器 → roll/pitch）| ❌ | 曲线显示、电机行、**诊断 CSV 的 roll/pitch 列**、位置环 |
| **模型角**（翻号+零位+钳制）| ✅ | `wrist_eval` → `R`、`s`；`positive_null_direction` → `n̂` |

> 说"没钳"指的是**显示/记录那一份原始位姿**，不是 R 绕过了角度。

---

## 4. 域的边界怎么来的

对 `RANGE_DEG` 做 5° 网格扫描（2026-11-20）：

```
        roll→  -25  -20  -15  -10   -5    0    5   10   15   20   25
pitch  45:     ✗    ✗    ✗    ✗    ✗    ✗    ✗    ✗    ✗    ✗    ✗
pitch  30:     ✗    ✗    ✓    ✓    ✓    ✓    ✓    ✓    ✓    ✗    ✗
pitch   0:     ✗    ✗    ✓    ✓    ✓    ✓    ✓    ✓    ✗    ✗    ✗
pitch -25:     ✗    ✗    ✓    ✓    ✓    ✓    ✓    ✓    ✗    ✗    ✗
```

取**保守边界**（四角均可行）：`FORCE_CLOSURE_ROLL_DEG = (-15, 10)`、`FORCE_CLOSURE_PITCH_DEG = (-25, 30)`。

`tests/test_force_closure_box.py` 会重算校验：
- 四角必须 `n̂ ≻ 0`；
- 边界外 5° 必须失败（防止盒画大了）；
- 区内恒等、区外钳到边界且可用、NaN 回中心、幂等。

## 5. ⚠ 钳制的代价（不要误解为"域外也能精确控力"）

| 真实 roll | 钳后 | `R` 相对误差 | 同一组 f → τ 的差 |
|---|---|---|---|
| 15° | 10° | 10.2% | 85.8 mN·m |
| 20° | 10° | 20.1% | 168.2 mN·m |
| **25°** | 10° | **28.7%** | **239.3 mN·m** |

整机力矩能力只有 ~420 mN·m ⟹ **域外误差达能力的 40~57%**。

**更根本**：域外那些位姿**物理上不可能三缆力封闭**（n̂ 不存在是几何事实）。
钳制让软件"跑起来"，**没有让物理变可行**。

| 目标 | 钳制能帮上吗 |
|---|---|
| 位姿越界时仍能"动"（回中途中）| ✅ 能 |
| 位姿越界时**精确控力矩** | ❌ 不能，先把腕移回域内 |
| 越界时"安全优先" | ⚠ 见 §6 |
