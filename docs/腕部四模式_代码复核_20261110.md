## 1. 讲解：四种模式其实是同一条流水线

### 1.1 每拍（10 ms）发生的 8 件事

`_cl_tick`（`mmhand_scope.py:5142`）是唯一的闭环入口，四个模式只在第 ⑧ 步分叉：

```
① dt = perf_counter 实测，钳 [1ms, 50ms]            :5149-5152
② armed ∧ connected 否则停环                        :5156
③ 反馈链 J16/J17: raw → unwrap_counts → 中值5 → EMA(0.10)
   → ×AXIS_SIGN → −基准 得 roll/pitch（deg，界面约定）  :5159-5176
④ 参数快照 20Hz 缓存（只有位置模式用）                 :5167-5171
⑤ 目标框每拍直读（输入路径不节流）                     :5177-5182
⑥ ⏺记录 → _record_calib_row（四模式都记）             :5183
⑦ 张力守卫（四模式都过）：过载→停环；过期→冻结；松绳→⚠   :5187
⑧ 模式分发                                          :5201-5209
```

**共用底座**（这是理解四模式的关键，也是这套代码最漂亮的地方）：

| 底座 | 作用 | 谁用 |
|---|---|---|
| `wrist_eval(θ)`（`wrist_model.py:90`） | 一次求值同时给 **绳长 l**（λ 地图）和 **力臂 R = −∂l/∂θ**（斜率） | 四模式 |
| `_incr_step`（`wrist_force_law.py:76`） | 增量 PI 基元：`du = sat(kp·e + sat(ki·∫e))`，`step=round(resid+du)`，条件积分 | 力控×3 |
| `_apply_force_step`（`mmhand_scope.py:4997`） | 三力控统一出口：`out = 实测位置 + step`，再夹 `base±trim限幅` | 力控×3 |
| `_clamp_per_tick` + `_send_motor_batch`（`:4807`、`:4969`） | 位置模式出口：绝对目标、每拍限幅、一帧 0xD3（30 路） | 位置 |
| 张力守卫 / `_effective_flimits` | 阈值单源（边界行 ∩ 观测台守卫框取严）、fail-closed | 四模式 |

### 1.2 位置模式：**有模型 ⇒ 绝对式**

`wrist_control_step_model`（`wrist_control_law.py:165`）：

```
θ_model = θ_rel + δ                          # δ 全链唯一零点校正（当前 0）
ff_i    = k_i · [ l_i(θ_tgt) − l_i(ref) ]     # ref = 启动瞬间实测位姿（2026-11-10 修复）
corr_i  = −kp · k_i · ( R_i(θ_fb) · e_rad )   # e = θ_tgt − θ_fb（过死区）
out_i   = clamp( origin_i + ff_i + corr_i , origin ± soft_limit )
```

两个必须知道的性质：

1. **前馈是精确的**：`l(θ)` 是解析闭式，不是 R 的线性近似；`R` 只用来做 P 校正。
2. **P 校正的符号是"助推"而不是"回拉"**：`corr` 与 `ff` 同向（代码自测
   `tests/test_wrist_control_law.py` 里写得很清楚："校正与误差同向，往目标继续推"）。
   所以指令 = 目标 + kp·e，理想一拍到位时误差每拍变号 ×(−kp)。

### 1.3 张力模式：**无模型 ⇒ 增量式**

`wrist_tension_step`（`wrist_force_law.py:295`）：每缆独立 `e_i = f*_i − f_i` → PI →
`trim_i = trim_sign_i · step_i` → `out = 实测位置 + trim`。

- 三个环**完全解耦**（对角），所以 `τ = R·f` 不受控：**"三缆各 2N" 不保持位姿**，
  腕会漂到 τ=0 的平衡位（重力/绳刚度决定）。这是它"最直观但也最不端到端"的原因。
- 没有"力→counts"的模型，因此只能用增量式（这是文档 §6 的论证，成立）。

### 1.4 张紧模式：**沿零空间单旋钮**

`wrist_tight_step`（`wrist_force_law.py:398`）：`t = f·n̂`（张力在零空间方向的分量），
`err = t* − t`，`e_i = err·n̂_i`，然后同一个增量基元。

- **τ ≈ 守恒**是因为步长向量 ∝ n̂ 且 `R·n̂ = 0`；整数化后每缆 ≤0.5c 偏差（文档已写）。
- `n̂` 只在 CAD 网格的 1957/3621 个位姿存在（全正），所以**张紧/力矩不是全行程可用**：
  可用窗约 roll∈[−18, +14.75]°、pitch∈[−20, +33.75]°（`wrist_model.py:111` 的判据）。
- `t` 本身**不是一个位姿无关的物理量**：`n̂` 随位姿变，同一组 f 在不同位姿给出不同 t。

### 1.5 力矩模式：**外环 τ PI → TDA 分配 → 内环张力 PI**

`wrist_force_v2_step`（`wrist_force_law.py:166`）：

```
① τ_meas = R·f
② e_τ = τ_d − τ_meas（死区 0.01）; u = sat(kp_τ·e_τ + I_τ, ±τ_lim)
③ f_d, α = TDA(R, n̂, τ_d + u, preload, fmin, fmax)      # P=[R;n̂ᵀ] 求逆，超界缩 τ 不缩 t
④ trim_i = trim_sign_i · _incr_step(f_d,i − f_i, P=I=trim_gain)
```

要点：
- 这不是论文 §7 的 `P⁻ᵀ` 关节空间解耦（作者自己在 `mmhand_scope.py:4898` 承认了）：
  **内环仍是逐缆对角 PI**，`R·Rᵀ` 耦合靠外环积分收敛，瞬态是耦合的。
- TDA 的"优雅降级"只缩力矩 `α`，不缩预紧 `t`；`α` 曲线就是"离不可达有多近"。
- **默认 `Kp_τ=100` 是个陷阱**：`u = 100·e`，而可达力矩量级 ~0.1 N·m，
  退出饱和的门槛 e≈1e-3 N·m 比死区 0.01 还小 ⇒ 实际长期停在 α<1 的饱和区
  （文档说实测 α≈0.065 正是此），外环积分按抗饱和规则被冻结。
  文档建议 1~5 是对的，但没写清"饱和 ⇒ 积分永远不工作"这层因果。

### 1.6 为什么两种执行器语义

| | 位置 | 张力/张紧/力矩 |
|---|---|---|
| 有 `θ → counts` 的解析映射吗 | **有**（`k·Δl`） | **没有**（"f 对应多少 counts"未知且非线性） |
| 因此 | 绝对目标（`origin + …`） | 增量目标（`实测 + step`） |
| 堵转时 | 目标固定，不漂 | 每拍从实测重算，不漂 |
| 限速 | `_clamp_per_tick` | `_incr_step(max_step)` |
| 稳态误差 | 有（P-only，靠死区） | 有（P 为主，I 被条件积分限制） |

### 1.7 必须记住的数值敏感点（我实算的，不是抄文档）

| 轴 | 每 1° 需要的 counts（C1/C2/C3） | 5 c/拍 对应的角速度 |
|---|---|---|
| ROLL | **+0.7 / +50.8 / −38.6** | ≈ **9.8 °/s**（C2 限速） |
| PITCH | **+132.1 / −26.7 / −24.8** | ≈ **3.8 °/s**（C1 限速） |

三条推论（文档里没有）：

1. **C1 对 ROLL 几乎无效**（0.7 c/°）——ROLL 实际是 C2/C3 两根绳在控，C1 只当预紧。
   PITCH 反过来，几乎全压在 C1 上。所以"三缆冗余"在控制通道上是不对称的。
2. **同一根"每拍限幅 5c"缰绳，在两个轴上差 2.6 倍**：ROLL 9.8°/s、PITCH 3.8°/s。
   走 25° 分别要 2.5 s 和 6.6 s。
3. **正弦带宽测试在默认参数下必然削顶**：±25°@0.2Hz 峰值 31.4°/s ⇒
   ROLL 需 **16.0 c/拍**、PITCH 需 **41.5 c/拍**，默认只有 5 c/拍。
   想做 0.2Hz 扫掠必须先把 `每拍限幅` 提到 ≥16（ROLL）/ ≥42（PITCH）。
   文档 §13.6 的"带宽 ≈2 Hz"只在小摆幅（≲1°）下成立。

## 2. 隐藏 BUG 详述

### R1（P0）`k` 与 `trim_sign` 的符号约定互相矛盾

同一个"counts 增大"被两处文档/注释定义成相反的事：

| 出处 | 说法 | 含义 |
|---|---|---|
| `wrist_calib.json` 的 note | "k = +130380 … counts 增大⇒放绳" | counts↑ = 绳变长 |
| `wrist_control_law.py:31` | "k_i 符号约定：counts 增大 ⟺ 绳放长" | counts↑ = 绳变长 |
| `mmhand_scope.py:2806` | "修正口径（2026-10-29 更正）：三台 counts↑=收绳 → 全 +1" | counts↑ = 绳变短 |
| `使用说明.md:190` | "trim_sign=+1 → counts 减 = 放" | counts↑ = 绳变短 |

**推导出的不变量**：`Δcounts = k·Δl`；而"张力↑ 需要绳变短"⇒
`sign(trim_sign_i) = −sign(k_i)` 必须成立。

**当前配置** `k = +130380, trim_sign = +1,1,1` **违反该不变量**。后果二选一：

- 若 k 的符号是对的（counts↑=放绳）⇒ `trim_sign` 应为 `−1,−1,−1`，
  **三个力控模式与一键松绳的方向全是反的**（力控=正反馈，只被 `trim限幅` 3000c 兜住；
  一键松绳会变成"收紧"）；
- 若 trim_sign 是对的 ⇒ k 应为 `−130380`，**位置环的前馈与 PID 同时反向**，变成发散环。

> 2026-11-10 过程记录：我一度按"k 应为负"改成了 `−130380`，用户确认原值后**已回滚为 +130380**。
> 也就是说现在这条不变量是按"k 正、trim_sign 正"的组合在跑，**中间必有一处要改**——
> 到底改哪个只能靠台架 `+100c` 点动判定，代码无法替硬件回答。

**已落地的检查（2026-11-10）**：`_sign_invariant_note()` 在"载入标定"和"启动闭环"两处
做纯读自检，违反时标定行红字 + 控制日志 ⚠ + 写进 `CL_START` 安全日志；**只提示不拦截**
（避免误判把用户锁在门外）。

**仍建议**：加一个"方向自检"按钮：闭环外用 +100c 点动、读该缆张力变化，自动推出 `trim_sign`
（或反推 k 的符号），把这条不变量变成一键操作而不是靠人记。

### R2（P0）没有反馈新鲜度看门狗

- 位置模式只看 `raw16/raw17 is None`（`:5161`），**没有时间戳**：
  一旦 P4 停发 `0x0B`，`_enc_filt_raw` 保持最后一个值，环继续按"卡住的角度"发目标。
- 力控模式 `_motor_pos_now`（`:3670`）在 `m{m}_abs` 缺数据时**回退到 `self.targets[m]`**：

  ```python
  v = channels[f"m{m}_abs"].buf.last()
  if v is None or isnan(v): return targets.get(motor) or soft_limit_base(motor)
  ```

  然后 `_apply_force_step` 做 `out = cur + n`。**cur 变成"上一帧指令"⇒ 步长直接累加**，
  等于开环斜坡，直到撞 `max_trim`（默认 3000c ≈ 59° on ROLL）或软限位。
- `_send_motor_batch` 只检查 `last_servo_abs_all` **非空**（`:4979`），而它在断连时
  也不清空（`_disconnect:3069` 只置 `rx_thread=None`），所以"旧快照"永远可用。

**建议**：给 `last_servo_abs_all` 和 `_enc_filt_raw` 加时间戳，闭环里
`age > 100ms ⇒ 冻结 + 提示 + 停环`；`_motor_pos_now` 的"回退到指令"只允许在
非闭环路径使用（闭环里应视为 STALE）。

### R3（P1）取消「模型前馈」= 目标回 `origin`

`_cl_tick` 的分支（`:5211`）只有"勾了模型且标定非空"才走 v2，否则落到
`wrist_control_step`（`:5244`）。而手填系数行 2026-11-03 已删除，
`_cl_gain_vals` 恒为 `(0,0)`（`:2668`），于是：

```
out_i = origin_i + 0·tgt + 0·tgt + kp·(0·e + 0·e) = origin_i
```

即**把三根绳拉回"使能那一刻"的位置**（每拍 5c，慢慢走过去）。同一个坑还有：
- 运行中取消 `ROLL环` + `PITCH环` 两个勾选（`:2599`、`:2603`，没有联动保护）⇒
  `roll_enabled=pitch_enabled=False` ⇒ `dl=0, corr=0` ⇒ 同样回 origin；
- 状态行此时写"未用模型前馈：仅保持"（`:5264`），**文案是错的**。

**建议**：`cl_model_check` 与两个轴勾选在 `cl_enabled` 时禁用（或改动即停环）；
`wrist_control_step` 分支改为"用实测位置当目标"（真·保持）或直接停环。

### R4（P1）位置模式 Kp 在默认限幅下失效（附仿真）

我用真实 `wrist_control_step_model` + 单轴对象（`k=130380`、目标 5°）跑了两个场景：

| 场景 | 首拍 | 最大过冲 | 收敛到 ±0.3° | 说明 |
|---|---|---|---|---|
| 理想对象（指令一拍到位，无限幅） | +8.27° | +3.27° | 5 拍（50 ms） | ≈ 文档 §12.0 的描述 |
| **交付默认：每拍限幅 5c** | +0.10° | **0** | **49 拍（0.49 s）** | 单调，无过冲 |
| 默认 + Kp=0.3 | +0.10° | 0 | 49 拍 | 与 Kp=0.6 完全相同 |
| 默认 + Kp=1.5 | +0.10° | 0 | 49 拍 | 与 Kp=0.6 完全相同 |

结论：
1. 因为指令每拍最多挪 5c（≈0.1°），**P 校正那一点点助推根本追不上速率限制**，
   实际是"速率限制型一阶逼近"，Kp 在 0.3~1.5 区间**完全不影响结果**（调它没反应）；
2. 文档 §12.0 的数值表（第 0 拍就走 360 counts、一拍到 6.8°）与本篇 §1 的
   "统一速度缰绳 5 c/拍"**自相矛盾**：360 counts 需要 72 拍；
3. §13.6 的"位置收敛 ~5 拍（50 ms）"在交付配置下不成立（是 49 拍）；
4. 反过来，如果哪天把 `每拍限幅` 调到 ≥300 c/拍（追平舵机），文档的过冲/振荡
   就会真的出现（首拍 +8.27°、过冲 65%），那时 `0.6` 这个 Kp 才真正在被"调"。

**建议**：要么把每拍限幅与 Kp 的关系写进文档（"带宽 = 5c/拍 ÷ c/°"），
要么把位置模式改成"每拍最大角增量"（deg/拍）而不是 counts/拍，两个轴才好一致。

### R5（P1）正弦扫掠不播种相位

`_on_sweep_toggled`（`:4349`）把 `_sweep_phase = 0`，而正弦分支（`:4403`）
`v = amp·sin(phase)` **完全不参考目标框里的现值**：

- 目标框原本在 +25°，勾"扫掠 + 正弦波" ⇒ 第一拍目标变 ≈0°（跳 25°）；
- `sweep_wave_combo` 没有 `connect`（`:2639`），三角↔正弦中途切换不会重新播种；
- 改"幅值/频率"也是立即生效、不播种 ⇒ 都会跳。

目前只被"每拍限幅 5c"兜住（变成 2.5~6 s 的慢速回中），但**语义上是目标阶跃**，
标定录制时会把这段阶跃录进去。

**建议**：勾选/切换波形时令 `phase = asin(clamp(v0/amp))`（并选同号单调支），
或直接令 `v0 = amp·sin(phase)` 反解相位。

### R6（P1）参数缓存"强制失效"被 `hasattr` 绕过

```python
# _start_closed_loop:4526
self._cl_param_cache = None          # 注释：起点刚刷新 → 缓存必须立刻失效

# _cl_tick:5168
if now_pc - self._cl_param_ts > 0.05 or not hasattr(self, "_cl_param_cache"):
    self._cl_param_cache = self._read_cl_params()
prm = self._cl_param_cache           # 可能是 None
if prm is None:
    self._stop_closed_loop("缺少电机起点")   # 误报
```

`_cl_param_cache` 一旦被赋过值，`hasattr` 永远为真，`None` 并不触发刷新。
于是"停止后 50 ms 内再启动"（手快、`_want_closed_loop` 自动起环、脚本连点）
⇒ 首拍读到 `None` ⇒ 立刻停环 + 报一个假原因。

**改法**：`... or self._cl_param_cache is None`。

### R7（P1）张紧模式：可行域漂移 ⇒ 中途停环，且原因被覆盖

`_tight_params`（`:4840`）每拍用**当前位姿**的 n̂ 重算可行域
`[fmin/min(n̂), fmax/max(n̂)]`；`t_tgt` 落不进去就 `return None`，
`_cl_tick_tight`（`:5091`）立刻 `_stop_closed_loop("张紧控制：参数非法或该位姿 R(q) 无效")`。

两个问题：
1. **可行域不是位姿无关的**：`t=5N` 在回中位可行，腕一旦漂到高位姿就可能不可行
   （文档 §9 自己举了 pitch 30° 时 `t≥12.7N` 的例子）⇒ 一个"能起环"的参数会在
   运行中把环停掉，而**停环后腕自由下垂**（hold 是刹在当前位置，不会回中）；
2. `_tight_params` 在 `quiet=False` 时已经把真实原因写进状态行（`:4870`），
   但**同一拍** `_stop_closed_loop` 又把它覆盖成通用消息，用户只看到"参数非法"。

**建议**：`t` 超上界时**钳到上界继续跑**（而不是拒绝）；超下界时提示
"预紧不足：请增大 t 或降低 fmin"；停环消息带上真实原因（把 `_tight_params`
的拒绝理由作为字符串返回）。

### R8（P1）力控增量基准 = 实测位置 ⇒ 有效速度被遥测率限制

```python
# _apply_force_step:5013
cur = self._motor_pos_now(m)     # 来自 0x03 舵机 ABS 帧
out = cur + n
```

如果舵机 ABS 帧率 < 100Hz（或与 10ms 定时器拍频打滑），**相邻两拍读到同一个 cur**
⇒ 两拍算出的 `out` 完全相同 ⇒ 第二拍是重复指令，实际只走了一步。
`resid` 的"小数进位"因此也失去意义（它假设每拍都真正执行了一步）。

**影响**：三个力控模式的实际速度上限 = `max_step × ABS帧率`，而不是
`max_step × 100`。位置模式不受影响（绝对目标）。
**验证**：看状态栏/遥测里的 `servo_abs` 计数（`rate_counters`），
若 <100Hz 就坐实；也可用 `tools/perf` 里的探针。
**建议**：用 `targets[m] + step`（指令累加）当基准、把 `实测` 只用于 `max_trim`
夹紧；或按"距上一帧 ABS 的时间"缩放步长。

## 4. 四模式的逻辑 / 理论 / 代码三层问题

### 4.1 逻辑层（状态机与模式切换）

### 4.2 理论层

**(a) 位置环：被速率限制主导的一阶系统，而不是文档里的"过冲振荡 P 环"**

- 理想（一拍到位）离散模型：`e_{n+1} = −kp·e_n` ⇒ 交替衰减，kp<1 稳定，与文档一致；
- 交付配置（5c/拍）：指令每拍最多走 0.1°，误差单调减小，**kp 不参与结果**；
- 真正的稳定性判据不是 `kp<1`，而是"kp 只在误差小到 `kp·e < 5c` 时才起作用"，
  即 `e < 5/(kp·c_per_deg)` ≈ 0.16°（kp=0.6, 50.8 c/°）——**比死区 0.3° 还小**。
  所以：**P 项基本永远被限幅吞掉**，所谓"P 校正"在实机上贡献的是"多走一点点"，
  文档 §11 里"限幅接管临界误差 e_c ≈ 0.17°"其实已经算出来了（`e_c = s/(kp·k·σ_min)`），
  只是没有把结论说透：**在默认参数下，位置环 ≈ 纯前馈 + 死区**。

**(b) 三力控：每拍增量型 PI 的稳定性由 `kp × 绳子刚度` 决定，且饱和段自带降增益**

单缆离散模型：`f_{n+1} = f_n + S·sat(kp·e_n + I)`，`S` = 该缆的 N/counts 刚度。
- 大误差时 `sat` 生效 ⇒ 变成恒速斜坡 ⇒ 天然稳定；
- 小误差时退化为 `f_{n+1} = f_n + S·kp·(f*−f_n)` ⇒ 收敛因子 `1 − S·kp`，
  稳定域 `0 < S·kp < 2`，**在 2 附近会出现围绕死区的极限环**；
- 而 `S` 是未知量（绳刚度/预紧/摩擦），默认 `Kp_f=10、Kp_t=50、trim_gain=50` 是**台架拍出来的**，
  没有裕度论证。文档应该补一句"若出现 ±1~2N 的等幅抖动，先把 Kp 减半"。
- 另外 `i_term` 的钳位用的是 `max_trim`（3000c，`:325`/`:421`），远大于输出饱和 `max_step`（5c），
  所以**积分钳位形同虚设**；真正防 windup 的是"条件积分"（`|raw|<max_step` 才累加），
  这一点文档写对了，但钳位参数是误导性的。

**(c) 张紧：τ 守恒的三个漏洞**

1. 整数化：每缆 ≤0.5c ⇒ `R·Δf` 不为 0（文档已写）；
2. **fmin 方向地板**（`:422`）只把某缆 `step` 清零，步长向量不再 ∝ n̂ ⇒ 守恒被破坏，
   文档只写了"地板不负责抬缆"，没写"地板期间 τ 不守恒"；
3. 地板清 `integ/resid` 但不清另外两缆 ⇒ 地板释放后会出现一次"单缆补步"。

**(d) 力矩：外环积分在饱和区被规则性冻结**

`alpha < 1` 就冻结 `integ_tau`（`:219`）。默认 `Kp_τ=100` 时几乎全程饱和 ⇒
**积分几乎不工作**，稳态力矩误差全靠高 P 硬顶；一旦 `τ_d` 接近可达上界，
系统会长期贴边（α≈0.06），表现为"推得动但推不到目标"。建议默认改 2~5，
并在状态行把 `α` 阈值（如 <0.95 连续 2s）做成提示。

**(e) 力矩模式其实不"解耦"**

内环逐缆对角 ⇒ `R·Rᵀ` 耦合（改 C1 张力会同时改两个轴的力矩），外环靠积分收敛。
作者在 `:4898` 已经诚实标注了。文档 §6/§13 用"解耦力矩"这个标题会让人误以为
是论文 §7 的 `P⁻ᵀ` 结构。建议标题改"力矩闭环（TDA 分配 + 腱空间内环）"。

## 5. 建议的台架验证顺序（约 30 分钟）

1. **方向自检（必做，R1）**：闭环外，三缆各 `+100c`，记录张力升降 ⇒ 定出真实
   `counts↑` 是收绳还是放绳；据此校正 `k` 的符号 **或** `trim方向`，
   并把"`sign(trim_sign) = −sign(k)`"写进加载检查。
2. **反馈断流（R2）**：闭环运行中拔掉 P4 上行（或屏蔽 encoder 帧），
   看是否还能继续发 0xD3；确认后加看门狗。
3. **位置模式 Kp 有效性（R4）**：同样 5° 阶跃，Kp=0.3/0.6/1.5 各跑一次，
   看曲线是否**完全重合**（预期重合）；再把每拍限幅提到 100c 重跑，
   过冲应出现（预期首拍 +8.3°）。这一步能让学生/评审直观看到"限幅才是主导"。
4. **正弦带宽（§1.7）**：±5°@0.2Hz 与 ±25°@0.2Hz 各跑一次，
   后者必然削顶；把每拍限幅提到 20 再跑。
5. **力控刚度/增益（4.2b）**：Kp_f 逐步 ×2，找到出现 ±1N 等幅抖动的点，
   把默认值定在它的 1/3。
6. **张紧可行域（R7）**：回中位起环 `t=5N`，手推到 pitch 25° 以上，
   看是否停环；确认后改成"钳到上界"。
7. **断流+力控（R2/R8）**：力控运行中断开舵机 ABS 帧，看 `trim` 是否一路涨到 3000。
